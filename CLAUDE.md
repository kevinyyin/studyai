## Commands

- `npm run dev` — start dev server (Turbopack, http://localhost:3000)
- `npm run build` — production build
- `npm run start` — run the production build
- `npm run lint` — ESLint (flat config in `eslint.config.mjs`)
- `npx tsc --noEmit` — type-check (there's no dedicated `typecheck` script)

There is no test suite in this repo.

### Environment

Requires `GOOGLE_GENERATIVE_AI_API_KEY` in `.env.local` — the flashcard-generation API route calls Gemini directly with this key. Without it, `/decks/new` submissions fail with a friendly in-app error; the rest of the app (browsing/studying existing decks) works fine without it.

## Architecture

### Data & persistence

There is no backend database or auth — everything lives in the browser's `localStorage`. `lib/types.ts` defines `Deck` (`id`, `title`, `createdAt`, `cards[]`, optional `summary`) and `Flashcard`. `lib/storage.ts` wraps `localStorage` (guarded for SSR — no-ops/returns `[]` when `window` is undefined) with `getDecks`, `getDeck`, `saveDeck`, `updateDeck`, `deleteDeck`.

Pages hydrate deck state in a `useEffect` after mount, since `localStorage` isn't available during SSR. This intentionally trips the `react-hooks/set-state-in-effect` lint rule and is silenced with a scoped `eslint-disable-next-line` plus a comment explaining why — that's the correct fix here, not removing the effect. Where state is instead derived from a changed prop (see `components/study-mode.tsx`), the render-time "adjust state during render" pattern is used instead of an effect, to actually satisfy the rule rather than suppress it.

### Generation flow

`components/note-input.tsx` posts notes text + uploaded files as `FormData` to `app/api/generate-flashcards/route.ts` — the only API route in the app. It calls Gemini once via the Vercel AI SDK (`generateText` + `Output.object()` with a Zod schema) to produce **both** a flashcard array and a condensed prose `summary` in a single pass. The client wraps the response into a `Deck`, saves it via `lib/storage.ts`, and redirects to `/decks/[id]`.

The model id is hardcoded in the route (currently `gemini-flash-latest`). Gemini model availability shifts over time — if generation starts failing with a 404 "no longer available to new users" error, that's the model id needing an update, not an application bug.

### Pages

- `app/page.tsx` — home: deck catalog list, "New deck" entry point
- `app/decks/new/page.tsx` — the notes-in / flashcards-out form (`NoteInput`)
- `app/decks/[id]/page.tsx` — study view: flip-card `StudyMode`, `CondensedNotes` summary block, `DeckCardsEditor` (edit/delete individual cards), delete-deck

### UI system — shadcn/ui on Base UI, not Radix

`components/ui/*` were generated by the shadcn CLI configured for **Base UI** (`@base-ui/react`), not the more common Radix primitives. This matters for anything polymorphic: use `render={<Link href="..." />}` instead of `asChild`, and pass `nativeButton={false}` on `Button` when rendering it as a non-`<button>` element (e.g. a link), or Base UI will warn in the console and lose native button semantics. Check an existing usage (e.g. `components/deck-list.tsx`) before adding a new trigger/render pattern.

### Design system

The app follows a deliberate "study catalog" visual language, not the default shadcn look — don't fall back to generic card grids or shadcn defaults for new UI. Warm paper/ink color tokens are defined in `app/globals.css` (`--brand`, `--brand-tint`, plus the standard shadcn tokens remapped to the palette). Instrument Sans is the display face (`font-display` utility, used sparingly for headings), Geist Sans is body text, Geist Mono is for catalog numerals and metadata (the `kicker` and `catalog-num` `@utility` classes in `globals.css`). Content is presented as hairline-divided lists with `N°04`-style numerals rather than card grids — follow this pattern for new list-like UI.

### Theming

Dark mode uses `next-themes` (`components/theme-provider.tsx`) with `attribute="class"`; `<html>` in `app/layout.tsx` has `suppressHydrationWarning` because the theme class is applied client-side. `components/theme-toggle.tsx` renders a disabled placeholder until mounted to avoid a hydration mismatch.

### Styling stack

Tailwind v4 — config lives entirely in `app/globals.css` via `@theme inline`; there is no `tailwind.config.ts`.

### Deployment

Git-linked Vercel project (production branch `master`, no staging branch) — pushing to `master` deploys straight to production.
